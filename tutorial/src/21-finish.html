You built the whole thing. This last chapter is a checklist to prove it all works together, a troubleshooting table, and a look at what the project plans next.

Type check the whole project

TypeScript can check every file without running anything:

pnpm typecheck

It runs nuxt typecheck, which uses vue-tsc to check both server and page code against the files Nuxt generates. A clean run prints no errors.

If it fails

Read the first error only. Most later errors are fallout from it. The file name and line number are given; open that line and compare with the code in the chapter.

The final checklist

  • pnpm dev starts without errors; /api/health says ok.
  • /api/nope answers a JSON NOT_FOUND with a request ID.
  • You can sign up, verify, sign in and call /api/me.
  • Onboarding completes; you can join a community and get Originals number 1.
  • An admin can publish a drop, you can like it and see it in the feed.
  • A mission completion adds XP once, never twice.
  • A reported drop appears in the admin report queue; an accepted application creates a community.
  • The API Explorer at / lists the operations and sends requests as you.
  • pnpm test:unit and pnpm test:e2e pass.
  • .env is not in git (git status never lists it).

When something goes wrong

NUXT_DATABASE_URL is not set.env missing or the dev server was started before you created it.Check .env has the line; restart pnpm dev.
Health shows "db":"error" and status 503The database container is stopped, or the URL is wrong.docker ps; docker start clautverse-pg.
relation "user" does not existMigrations were not applied.set -a; . ./.env; set +a then pnpm db:migrate.
pnpm db:migrate complains about the URLThe shell did not load .env (drizzle-kit does not read it by itself).Run the set -a; . ./.env; set +a line in the same terminal window.
Sign-up works but sign-in says email not verified (403)This is correct behaviour.Click the link printed in the server terminal, or run the SQL shortcut from chapter 8.
ONBOARDING_REQUIRED when joiningThe fan has not completed onboarding.Finish chapter 10's complete call.
FORBIDDEN on /api/admin/*The account is not an admin.Run the chapter 17 SQL to grant super_admin.
Cursor errors (Invalid cursor)NUXT_CURSOR_SECRET changed, or the cursor came from a different list.Start again from page one.
Changed nuxt.config.ts but nothing happenedThe dev server needs a restart for config changes.Stop and rerun pnpm dev.
Port 5432 already in useAnother PostgreSQL is running on your machine.Stop it, or map Docker to another port and update NUXT_DATABASE_URL.
Explorer dropdowns are emptyYou are signed out (some lists are private), or the list is empty.Sign in at the top of the page; create data.

What is deliberately missing

  • Uploads (images, voice): routes that need them answer FEATURE_DISABLED.
  • Deployment: this guide runs everything on your machine. The project is designed for a hosted Postgres (it mentions Neon) and a scheduler to call the two job routes from chapter 14, but deployment steps are outside this guide.
  • A real front end for fans: only the API Explorer exists.

Where to go from here

  1. Build a feature of your own end to end: a table in the schema, a migration, an endpoint with Zod and requireUser, an entry in the contract, a test. That one exercise uses every chapter.
  2. Read docs/specs/ecosystem-prd.md in the repository to see the product the code is aiming at.
  3. Pick one skill to deepen: SQL and transactions, Vue components, or TypeScript types. This project exercises all three.

If you can explain, in your own words, how a request to join a community travels from the address bar to the database and back, you understand this project. Chapter 0's journey list and chapter 11 are the two places to reread.
