Up to now you tested with curl. Here you build the page that does the same thing with buttons and forms: the API Explorer. It is the only screen in the project, and a good first look at Vue inside Nuxt 4.

What it does

  • Shows every operation from the OpenAPI contract, grouped by tag, with a search box.
  • Has a sign-in / sign-up strip at the top, so requests run as a real user through the same session cookie you used in curl.
  • Each operation is a card. Open it to see parameters and body fields as the right kind of input (dropdown for fixed choices, a picker of real records for IDs, number boxes that enforce limits), press Send request and see the status, timing and JSON answer.

Vue and Nuxt in five minutes

A web page is built from components: small reusable pieces (a button, a card, a top bar) that each own their appearance and behaviour. Vue is the library for writing components. Nuxt adds conventions so you write less setup.
  • A .vue file has up to three blocks: <script setup lang="ts"> (logic), <template> (HTML with extras), and optional styles. Here styling lives in one shared CSS file.
  • ref(x) makes a reactive value: when it changes, the page updates. You read and write it with .value in script, but just by name in the template. computed(() => …) is a value derived from others. reactive({}) is a reactive object. watch(source, fn) runs code when something changes.
  • Template extras: v-if / v-else (show or hide), v-for (repeat), v-model (two-way link between an input and a value), :prop="value" (bind an attribute to JavaScript), @click="fn" (handle an event).
  • Nuxt conventions used here: a file in app/pages/ is a route (index.vue is /); components in app/components/ are used without importing, and a subfolder becomes a prefix (components/docs/AuthPanel.vue is <DocsAuthPanel>); exported functions in app/composables/ are auto-imported; and Vue's ref, computed, watch, onMounted are auto-imported too.

Step 1: composables (the logic)

A composable is a plain function holding logic that components share. The first one fetches and understands the contract. Create app/composables/useOpenApi.ts:

  • The interface blocks describe the shapes we read from the contract, so the editor can autocomplete them.
  • specOperations(spec) flattens the nested paths → methods into one simple list of operations, pulling out our x-route-id, x-status and x-services fields.
  • describeSchema writes a short rule such as string · uuid or one of: a, b; bodyFields flattens a request body into table rows; groupByTag builds the sidebar groups.
  • useOpenApi() calls /api/_docs/openapi (chapter 18) with useAsyncData, which fetches on the server for the first paint and shares the result across components.

The second composable fills dropdowns with real records, so you pick an existing community instead of pasting a made-up ID. Create app/composables/useLookup.ts:

  • BY_FIELD maps a field name (communityId) to the list endpoint that holds valid values (/api/communities). BY_PATH does the same for a path parameter called plain id, by looking at which route it belongs to.
  • Each list is fetched once and cached in a Map, so ten cards asking for communities cause one request. A failed request (for example, not signed in) gives an empty list.
  • reloadLookups() refetches everything. The sign-in strip calls it after signing in or out, because some lists are private.
  • import.meta.client guards the fetch so it only runs in the browser.

Step 2: small components

One input that picks its own type from the field's rule. Create app/components/FieldInput.vue:

  • defineProps declares what the parent passes in; defineModel makes v-model work on this component.
  • The template is a chain of v-if / v-else-if: fixed choices → dropdown; list of IDs → multi-select; known record list → dropdown; number → number box clamped to its min and max; date-time → date picker; otherwise plain text.
  • The computed({ get, set }) blocks convert between what the user types and what the API needs (for example a local date-time becomes an ISO 8601 string with an offset, which chapter 12's Zod shapes demand).

Step 3: the endpoint card

The biggest component. Create app/components/ApiEndpoint.vue:

  • Looking itself up. It receives only a method and path, finds its operation in the contract, and splits its parameters into path, query and header groups.
  • Two ways to edit the body. The form fields and the JSON box stay in sync: setField writes into the object and re-prints the JSON; a watch on the JSON text parses it back when it is valid.
  • fillSamples() fills every input with the contract's examples, replacing made-up IDs with real ones where useLookup has some.
  • send() builds the final address (resolvedPath swaps {id} and appends the query string), sends it with the browser's fetch, and shows status, time and the pretty-printed answer. A status colour comes from statusClass (2xx ok, 4xx client error, 5xx or 0 server error).
  • The Idempotency-Key header gets a Generate button (chapter 12).

Step 4: the page and the app shell

app/pages/index.vue assembles everything. Create the pages folder first:

  • It fetches the contract, groups it by tag, and applies the search box's text with a computed filter.
  • <ApiEndpoint v-for="op in g.items" … /> renders one card per operation. The :key helps Vue keep cards stable when the filter changes.
  • useHead({ title }) sets the browser tab title.

Step 5: styles, images and config

The look is one hand-written stylesheet. It is long and purely visual, so copy it rather than type it: open and use the Copy button, saving it as app/assets/css/docs.css. Two helper images are used: public/clautverse-ghost.png (the logo in the top bar) and public/favicon.png (the tab icon). Use any PNG files with those names, or change the paths in Topbar.vue and app.vue.

Finally, finish nuxt.config.ts. After this step it matches the project's file exactly. Compare yours to:

  • css: ['~/assets/css/docs.css'] loads the stylesheet on every page.
  • routeRules: { '/docs/**': { redirect: '/' } } sends old documentation links (from the removed docs app) to the Explorer.

Restart pnpm dev and open http://localhost:3000/. You should see the API Explorer with a list of groups on the left. Then:

  1. Type health in the filter, open GET /api/health and press Send request. You should see a green 200 and the health JSON.
  2. Sign in with the verified account from chapter 8 using the strip at the top, then open GET /api/me and send it. You should see your profile.
  3. Open POST /api/communities/{id}/join, press Fill with sample data, and notice id becomes a dropdown of real communities and lane a dropdown of the six lanes.
