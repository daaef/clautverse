Almost everything in Clautverse is remembered: people, communities, posts, points. In this chapter you start a database and describe its tables. The next chapter connects the app to it.

Start PostgreSQL with Docker

No Docker? You can install PostgreSQL directly instead. See PostgreSQL without Docker for installs and drop-in replacements for every Docker command. The guide uses PostgreSQL 17.

A database is a program that stores data safely and answers questions about it quickly. Docker lets you run that program in an isolated "container" so you do not have to install and configure it yourself. If you delete the container you delete the database, which is perfect for learning.

With Docker Desktop open, run this one command (it is the same one the project's README uses):

docker run -d --name clautverse-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=clautverse -p 5432:5432 postgres:17
  • -d: run in the background.
  • --name clautverse-pg: a name so you can find it later.
  • -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=clautverse: set the password to postgres and create a database called clautverse. (Fine for a throwaway local database; never use this password anywhere real.)
  • -p 5432:5432: make the database reachable at port 5432 on your computer.
  • postgres:17: the program and version to run.

docker ps lists clautverse-pg with status "Up". If you restart your computer, start it again with docker start clautverse-pg.

Your .env already points at it. The line is NUXT_DATABASE_URL=postgres://postgres:postgres@localhost:5432/clautverse, which reads as postgres://user:password@host:port/database.

What an ORM does

A table has columns (like a spreadsheet's headings) and rows (the entries). Drizzle lets us describe each table in TypeScript, once. From that one description we get the real table, and also a typed way to ask for rows, so the editor warns us if we mistype a column name.

Drizzle is a "schema-as-code" ORM. A table is a pgTable('name', { columns }) call. Its helpers $inferSelect and $inferInsert give you the TypeScript type of a row you read or write. Column names in the database are snake_case (created_at); the TypeScript keys are camelCase (createdAt).

Things worth noticing:

  • user.username, dateOfBirth, roles, status, onboardingStatus are Clautverse's own columns. roles is a comma-separated text such as fan,talent.
  • status can only be active, suspended or pending_deletion. The { enum: [...] } option gives TypeScript that restriction.
  • references(() => user.id, { onDelete: 'cascade' }) means "this column points at a user; if the user is deleted, delete this row too". That is how a session disappears with its user.
  • timestamp(..., { withTimezone: true }) stores moments in time with their time zone, which avoids a whole class of date bugs.

Patterns repeated in this file, so you recognise them later:

  • uuid('id').primaryKey().defaultRandom(): every row gets a random unique ID.
  • unique(...) and uniqueIndex(...).where(...): rules like "one membership per user per community" or "only one pending application per user". The database itself enforces them, so no bug in our code can break them.
  • index(...): makes lookups and sorted lists fast. The index on (communityId, publishAt, id) exists because the feed asks for exactly that order.
  • Counters such as memberCount and likeCount are stored on the row (denormalised) so lists do not need to count thousands of rows each time.
  • Append-only tables (xp_transaction, admin_audit): the app only ever inserts. History is never rewritten.
