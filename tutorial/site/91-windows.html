    Appendix

    Setting up on Windows

    About 6 min read

    The guide's commands are written for macOS and Linux terminals. On Windows you have two good choices. Pick one, then follow the guide as written.

    Choose how you will work#

    OptionWhat it isEffect on this guide
    A. WSL 2 with Ubuntu (recommended)A real Linux terminal that runs inside Windows.Every command in the guide works exactly as written. Follow the Linux notes in this appendix.
    B. Git BashA bash-style terminal installed with Git for Windows.Most commands work as written. Docker and Node run natively on Windows.
    C. PowerShell onlyWindows' own terminal.Several commands differ. See "PowerShell translations" below.

    In plain words

    A terminal is where you type instructions. Windows' default terminal speaks a different "language" from the Mac/Linux one the guide uses, like a different dialect. WSL gives you the other dialect, so nothing needs translating.

    Option A: WSL 2 (recommended)#

    1. Open PowerShell as administrator (right-click the Start button) and run wsl --install. Restart when asked, then finish creating your Ubuntu username and password.
    2. Open "Ubuntu" from the Start menu. From now on, use this window for everything.
    3. Install Node.js 24 inside Ubuntu. A common route is nvm: install it from github.com/nvm-sh/nvm, then run nvm install 24.
    4. Install pnpm and Git: npm install -g pnpm, and sudo apt install git.
    5. Database: install Docker Desktop for Windows and tick "Use the WSL 2 based engine" (it is the default), or follow PostgreSQL without Docker inside Ubuntu.
    6. Keep your project inside the Ubuntu file system (for example ~/clautverse), not under /mnt/c. It is much faster.

    Checkpoint

    In Ubuntu: node -v prints 24 or higher, pnpm -v and git --version print versions, and docker -v works if you chose Docker. Then continue with chapter 1.

    Option B and C: install the tools natively#

    Open PowerShell (not as administrator unless an installer asks). winget is Windows' built-in installer. If a package name is not found, run winget search nodejs and use the ID it shows.

    Close and reopen PowerShell so it sees the new programs, then check:

    node -v must print 24 or higher (the project's package.json requires >=24). If it prints less, install the newer Node from nodejs.org.

    Then pnpm:

    Watch out

    "running scripts is disabled on this system" is a common first error on Windows. It means PowerShell refuses to run pnpm. Run this once to allow scripts you installed yourself, then retry: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

    The database

    • Docker route: winget install Docker.DockerDesktop (or download from docker.com), restart, and start Docker Desktop. It needs WSL 2 or Hyper-V; the installer guides you. Then chapter 4's docker run command works in PowerShell as written (it is one line).
    • Without Docker: use the PostgreSQL installer and the appendix.

    In programming terms

    esbuild (used by Nuxt) runs a small install step. The project's pnpm-workspace.yaml already allows it (chapter 2). If pnpm asks which build scripts to allow, choose esbuild. No package here needs a C++ compiler, so you do not need Visual Studio Build Tools.

    Why not just use PowerShell?

    You can, but the chapters' checkpoints use many curl commands with JSON. In WSL or Git Bash they paste in unchanged. If you only want the Explorer page (chapter 19), you can skip curl entirely and test through the browser.

    Windows-specific problems#

    You seeCauseTry
    pnpm : File … cannot be loaded because running scripts is disabledPowerShell execution policy.Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
    'node' is not recognizedThe terminal was open during install.Close and reopen it.
    Docker says WSL 2 is not installedDocker needs WSL 2.Run wsl --install in an administrator PowerShell, restart.
    Very slow installs or file watching in WSLProject is under /mnt/c.Move it into the Ubuntu home folder.
    Line-ending warnings from git (LF will be replaced by CRLF)Windows uses a different line ending.Harmless; or run git config --global core.autocrlf input.
    Port 3000 or 5432 already in useAnother program uses it.Close it, or change the port mapping.

    This appendix was written from the project's files and general Windows knowledge. Nothing in it was run on a Windows machine, so if a command differs on yours, trust the error message and the tool's own website.
