    Part 6 · Explorer and tests

    The API contract (OpenAPI)

    About 4 min read

    So far the only description of our API is the code. This chapter adds a second one that machines and humans can both read: an OpenAPI contract. Then we add the one endpoint that serves it to the API Explorer.

    What OpenAPI is#

    In plain words

    A restaurant has a menu so customers know what they can order without walking into the kitchen. OpenAPI is the menu for an API: for each address it lists the method, what you must send, and what the answers look like. Tools can read it to build documentation pages, test clients and, in our case, the API Explorer.

    In programming terms

    OpenAPI (version 3.1 here) is a YAML or JSON file. The project keeps it by hand at openapi/clautverse.yaml and treats it as the source of truth for the Explorer. It is about 3,400 lines for roughly 110 operations, which is why this guide teaches the structure instead of asking you to type all of it.

    Anatomy of the file#

    The top of the file names the API:

    Under paths: each address has one entry per method. This is the simplest one, the health check:

    • operationId and x-route-id: the route's short name (OPS-01). Names starting with x- are our own additions. The same IDs appear in comments at the top of the route files (such as // OPS-01).
    • tags: the group in the Explorer's sidebar (OPS, COM, ADM…).
    • x-status: implemented, planned or deferred. The Explorer shows a coloured badge for anything not implemented.
    • responses.default points at a shared error description defined once, below.

    An operation that takes input adds parameters (for the path, the query string, headers) and a requestBody. Here is the join operation from chapter 11:

    Notice how each field describes itself: type, format, allowed values (enum), limits (minimum, maxLength), and an example. The Explorer turns exactly these into dropdowns, number boxes with limits and sample data. That is why the contract matters to the page you build in chapter 19.

    Finally, shared pieces live under components, so they are written once:

    The Error schema there lists the same error codes as chapter 6, and Page describes the { items, nextCursor } shape from chapter 7.

    Create your own starter file#

    In plain words

    You do not have to write 110 entries to continue. Start with a few and add more whenever you like. Each new route needs an entry that follows the join example above.

    Create openapi/clautverse.yaml with the header above, the /api/health block under paths:, and the components: section. To get the complete contract, copy the file from the project repository; it is the exact one the Explorer in this guide shows.

    The route that serves the contract#

    The browser cannot read a YAML file from the project folder, so we add an endpoint that reads it, converts it to JSON and sends it. It also adds one extra feature: for every operation it works out which parts of the system the route uses and attaches them as x-services labels (the little chips on each Explorer card). Create server/api/_docs/openapi.get.ts:

    • Caching by file time. The parsed contract is kept in memory and only rebuilt when the file's modification time changes, so edits show up without restarting.
    • routeKey converts a route file name to a contract path ([id] becomes {id}, index disappears), the reverse of chapter 3's rule.
    • utilExports and servicesPerRoute read every util file, collect the names it exports, then search each route file's text for those names. A route that mentions requireUser gets the "Session guard" chip. It is a simple text scan, not magic: it can only be as accurate as the names are distinctive.
    • If anything fails, it answers 500 OpenAPI spec unavailable.

    In programming terms

    The folder name _docs has no special meaning to Nitro; the leading underscore is just a naming habit. The address is /api/_docs/openapi.

    Checkpoint

    Restart pnpm dev and fetch it:

    You should see JSON starting with {"openapi":"3.1.0","info":{"title":"Clautverse API"… and then the paths. Commit: git add -A && git commit -m "OpenAPI contract and docs endpoint".
