    Part 3 · People

    Categories, Stars and onboarding

    About 3 min read

    A new fan's first job is to choose what they are into. This chapter adds the public lists (categories, countries, Stars) and the three onboarding endpoints that save the fan's choices as they go.

    Shared helpers#

    Create server/utils/catalog.ts:

    • list(items) wraps a short list in the same { items, nextCursor } shape as paged lists, with nextCursor: null. It keeps all list answers looking alike.
    • validateSelections checks that the picked category exists and is active, and that every picked Star exists and belongs to that category. If anything is wrong it throws one VALIDATION_FAILED whose details.fields names each problem, such as talentIds[1]: not_in_category.

    In plain words

    Onboarding is a short checklist: pick a category, pick favourite Stars, review. nextStep tells the app which step to show next, so a fan who closes the app halfway resumes where they stopped.

    The onboarding endpoints#

    server/api/onboarding/index.get.ts returns where the fan is:

    server/api/onboarding/index.put.ts saves partial progress:

    • PUT here means "store this version of my picks". It merges what arrived with what was saved before, so sending only categoryId keeps earlier Star picks.
    • insert(...).onConflictDoUpdate(...) is an upsert: create the row if it does not exist, otherwise update it. The onboarding table has one row per user, so this is safe to repeat.

    server/api/onboarding/complete.post.ts finishes it:

    • Needs a category and at least one Star (.min(1, 'pick at least one Star')).
    • Marks the user's onboardingStatus as completed and saves the picks in one transaction.
    • From now on, requireUser(event, { onboarded: true }) (chapter 8) lets this fan into endpoints such as joining a community. Others answer ONBOARDING_REQUIRED.
