## Outcome

You'll know which part of the code handles each step of a request, so the other guides make sense.

## Concept map

React and Vue are **UI libraries**: they draw screens. Next.js and Nuxt are **frameworks** built around them that add routing, server code and builds. Clautverse uses **Nuxt** (built on Vue). Its server engine, **Nitro**, runs the API.

| Concept | Clautverse (Nuxt/Nitro) | React/Next.js equivalent |
|---|---|---|
| API route file | `server/api/onboarding/complete.post.ts` | `app/api/onboarding/complete/route.ts` exporting `POST` |
| Shared server helpers | `server/utils/*` (auto-imported) | a `lib/` folder you import yourself |
| Request middleware | `server/middleware/*` | `middleware.ts` |

::guide-section{id="request-lifecycle" title="Request lifecycle" type="explanation" references="Nitro routing https://nitro.build/guide/routing|Drizzle ORM https://orm.drizzle.team/docs/overview"}
1. `server/middleware/00.request-id.ts` gives every request an ID and returns it in the `X-Request-Id` header.
2. Nitro picks the route file from the URL and method, e.g. `POST /api/onboarding/complete` → `server/api/onboarding/complete.post.ts`.
3. The handler calls `requireUser(event)`. It checks the Better Auth session cookie, account status and email verification.
4. `readJsonBody(event, schema)` checks the body with Zod. Bad input becomes a `VALIDATION_FAILED` error.
5. The handler reads and writes PostgreSQL through Drizzle (`useDb()`).
6. Any thrown `apiError(...)` is turned into the shared error envelope by `server/error-handler.ts`.
::
