## 5. Communities, memberships, Originals

#### COM-01 `GET /api/communities` — CONFIRMED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/communities.test.ts`
- **Purpose:** Browse/search communities (Discover, onboarding suggestions).
- **Caller:** Public (`viewerMembership` populated if signed in).
- **Query:** `q?`, `talentId?`, `showId?`, `sort = popular | newest | name` (default `popular`), `limit`, `cursor`.
- **200:** `{ items: CommunityCard[], nextCursor }`. Sort keys: `popular` → `memberCount desc, id desc` (decision 20.7); `newest` → `createdAt desc, id desc`.
- **Errors:** `VALIDATION_FAILED` (bad sort, cursor from a different sort).
- **Tests:** vetoed community never listed; cursor reuse across sort → 400; stable pagination under concurrent joins (memberCount change mid-pagination — see note).
- **Note:** sorting by a mutable `memberCount` can shift items between pages. Proposed mitigation: cursor snapshots the sort value; accept rare duplicates/skips on "popular", or compute popularity in a periodic job. **Flag for you.**

#### COM-03 `POST /api/communities/:id/join` — CONFIRMED (decision 6: permanent Originals)

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/communities.test.ts`
- **Purpose:** Fan joins → sees full posts; first 100 become Originals.
- **Caller:** Signed-in, verified, onboarded user (else `ONBOARDING_REQUIRED`), not suspended. No XP requirement.
- **Body:** `{ alertsEnabled?: boolean (default true) }`.
- **201 (new) / 200 (already active member):** `Membership` (includes `originalPosition` 1–100 or `null`).
- **Errors:** `NOT_FOUND` (community missing/vetoed); `ACCOUNT_SUSPENDED`; `FORBIDDEN reason:"removed"` (previously removed by owner/admin).
- **Concurrency:** single transaction: `INSERT ... ON CONFLICT (user_id, community_id) DO NOTHING`; Originals position assigned via `UPDATE communities SET originals_assigned = originals_assigned + 1 WHERE id = $1 AND originals_assigned < 100 RETURNING originals_assigned` (row-locked counter) — guarantees ≤100 under concurrency (acceptance #6).
- **Rejoin after leave:** reactivates the same row and **keeps** the original position. Positions are assigned to the first 100 *ever* to join and never reassigned; once 100 have been assigned, Originals is closed. Users `removed` by an admin lose their position (retired, not reassigned).
- **Side effects:** `memberCount` +1; no notification; no XP.
- **Tests:** double join → one row, second response 200 with same id (acceptance #4); 150 concurrent joins → exactly 100 non-null unique positions 1..100 (acceptance #6); vetoed community 404; suspended → 403.
