## 3. Onboarding / catalog

Catalog reads are **public** (no session) so the landing/onboarding screens work before signup. Inactive categories are returned with `active: false` (shown as "coming soon", not selectable). Catalog lists are small and bounded, so they return the pagination envelope with `nextCursor: null` always, to keep one list shape (lets us paginate later without a breaking change).

#### CAT-01 `GET /api/categories` — CONFIRMED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose:** Onboarding step 1 — show Reality TV active and others "coming soon".
- **Caller:** Public. **Query:** none.
- **200:** `{ items: Category[], nextCursor: null }` sorted `sortOrder asc, id asc`. Includes inactive categories with `isActive: false`.
- **Errors:** none beyond `INTERNAL`.
- **Tests:** Reality TV `isActive: true`; others present but `false` (acceptance #1).

#### CAT-02 `GET /api/countries?categoryId=` — CONFIRMED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose:** Onboarding — optional filter for the show list. "Country" is the **show's** country (catalog data: countries with active shows).
- **Query:** `categoryId?` (UUID) — only countries with ≥1 active show in that category.
- **200:** `{ items: Country[], nextCursor: null }` sorted `name asc`.
- **Errors:** `VALIDATION_FAILED` (bad UUID). Unknown `categoryId` → empty list, not 404.
- **Tests:** filters by category; inactive category returns empty list.

#### CAT-04 `GET /api/seasons?showId=` — CONFIRMED

#### CAT-05 `GET /api/talents?seasonId=&showId=&q=` — CONFIRMED (**rename** of PRD `GET /api/stars`)

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Why rename:** the data model entity is `Talent`; "stars" mixes UI copy ("Rising Star") with the resource name. Keep "Rising Star" as UI label only. *If you prefer `/api/stars`, say so — it's cosmetic.*

- **200:** `{ items: TalentCard[], nextCursor }` sorted `name asc, id asc`. Only `status = active` talents.
- **Errors:** `VALIDATION_FAILED` (no filter supplied — avoids dumping the whole table).
- **Tests:** season filter; unclaimed talents included with `isClaimed: false`.

#### ONB-01 `GET /api/onboarding` — PROPOSED (missing in PRD; required by "can be resumed if incomplete")

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose:** Resume onboarding where the fan left off.
- **Caller:** Signed-in user (self).
- **200:** `{ status: 'not_started'|'in_progress'|'completed', step: string | null, selections: { categoryId?, countryId?, showIds?, seasonIds?, talentIds? }, completedAt | null }`.
- **Errors:** `UNAUTHENTICATED`.
- **Tests:** new user → `not_started`; after ONB-02 → saved selections returned.

#### ONB-02 `PUT /api/onboarding` — PROPOSED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose:** Save a step's progress (partial draft).
- **Body:** `{ step, selections: {...partial} }`. Each referenced ID must exist and be active.
- **200:** same as ONB-01, `status: "in_progress"`.
- **Errors:** `VALIDATION_FAILED` (unknown or inactive ID — `details.fields["selections.showIds[1]"] = "inactive"`). After completion, the same route edits preferences (no `INVALID_STATE`).
- **Idempotency:** `PUT` replaces the draft; repeat = same result.
- **Tests:** inactive category ID rejected (acceptance #1); draft persists across sessions.

#### ONB-03 `POST /api/onboarding/complete` — CONFIRMED (decision 2b)

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts` · guide: [ONB-03](/onboarding/complete-onboarding)
- **Purpose:** Finish onboarding → land on feed/suggested communities.
- **Body:** `{ categoryId, countryId?, showIds: string[1..20], seasonIds?, talentIds? }`. Required: active `categoryId` (Reality TV) + ≥1 active `showId`; country/seasons/talents optional. Progress from ONB-02 is resumable.
- **200:** `{ onboarding: <ONB-01 shape, status: "completed">, suggestedCommunities: CommunityCard[] (≤10) }`.
- **Errors:** `VALIDATION_FAILED` (missing required field, non-existent/inactive IDs, show not in category/country); `UNAUTHENTICATED`.
- **Idempotency:** repeating → `200` with the stored selections; after completion, preference changes go through ONB-02.
- **Side effects:** stores `UserInterest` rows; sets `user.onboardingStatus = completed`. **Does not** auto-join communities (joining assigns Originals positions, so it must be an explicit fan action).
- **Tests:** happy path then `GET /api/me` shows `completed` (acceptance #3); inactive category rejected; repeat call idempotent; unauthenticated → 401.
