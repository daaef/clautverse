## 2. Account / auth

> **Auth is provided by Better Auth (decision 1),** mounted as one Nitro catch-all `server/api/auth/[...all].ts`. Better Auth owns the sign-up/sign-in/sign-out/verify/reset endpoints below; exact sub-paths follow the pinned Better Auth version and are copied into the OpenAPI file at scaffold time. Those endpoints return Better Auth's own error format (documented exception to §1.2); every Clautverse-owned route uses the §1.2 envelope. Launch login = **email + password**; Google sign-in later (Better Auth `account` table already supports extra providers, so no migration needed).

#### AUTH-01 `POST /api/auth/sign-up/email` (Better Auth) — CONFIRMED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose / journey:** New fan creates an account from the landing page.
- **Caller:** Unauthenticated. Rate limit 10/min/IP.
- **Body:** `{ email, password (8–128), name, username, dateOfBirth: 'YYYY-MM-DD', acceptTerms: true }`. Under-18 on the signup date → `VALIDATION_FAILED` `fields.dateOfBirth = "under_minimum_age"` (decision 2a: 18+). DOB is stored, never returned in any public shape. A verification email is sent via Resend; the user cannot use the app until verified (decision 1c).
- **200/201:** `201 Me` + session cookie set. `onboardingStatus: "not_started"`.
- **Errors:** `VALIDATION_FAILED` (email format, username rules, password policy); `CONFLICT` (`details.field: "email"|"username"`) — note: returning email-taken leaks account existence; PROPOSED to return a generic success and send an email instead (PROPOSED, since verification email is sent anyway).
- **Idempotency / side effects:** Creates `User`. No XP, no audit. Sends the verification email (Resend).
- **Tests:** creates user + sets HTTP-only cookie; duplicate username → 409; weak/invalid input → 400 with field map; password never in response or logs.

#### AUTH-02 `POST /api/auth/sign-in/email` (Better Auth) — CONFIRMED · unverified users get Better Auth's email-not-verified error and can request a new link (AUTH-04b). A user in `pending_deletion` who signs in within 30 days is restored (AUTH-08).

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose:** Returning user signs in. **Caller:** Unauthenticated, 10/min/IP.
- **Body:** provider-dependent (`{ email, password }` or magic-link/OAuth start).
- **200:** `Me` + session cookie.
- **Errors:** `UNAUTHENTICATED` with one generic message for wrong email *or* password; `ACCOUNT_SUSPENDED`; `RATE_LIMITED`.
- **Tests:** wrong password and unknown email give identical response; suspended user cannot sign in; cookie flags HttpOnly/Secure/SameSite.

#### AUTH-03 `POST /api/auth/sign-out` (Better Auth) — CONFIRMED

Status: :badge[implemented]{color="success"}

#### AUTH-05 `GET /api/auth/username-check?username=` — PROPOSED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose:** Live availability check while typing a username at signup/settings.
- **Caller:** Public, 30/min/IP. **Query:** `username` (PROPOSED rules
- **200:** `{ username, available: boolean, reason: null | "taken" | "reserved" | "invalid" }`.
- **Errors:** `VALIDATION_FAILED` if param missing; `RATE_LIMITED`.
- **Tests:** taken/reserved/invalid/available cases; case-insensitive (`Ada` vs `ada`); rate limit enforced. Note: final uniqueness is enforced by a DB unique index at write time, not by this check.

#### AUTH-06 `GET /api/me` — CONFIRMED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose:** App boot — who am I, which roles, has onboarding finished.
- **Caller:** Signed-in user (suspended users get `ACCOUNT_SUSPENDED`).
- **200:** `Me`.
- **Errors:** `UNAUTHENTICATED`.
- **Tests:** 401 without session (acceptance #2); returns no password hash, provider tokens or internal flags; roles reflect accepted talent application.

#### AUTH-07 `PATCH /api/me` — CONFIRMED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- **Purpose:** Settings → edit profile.
- **Caller:** Signed-in user, own record only (no `:id` in path, so no IDOR surface).
- **Body (all optional):** `{ username?, displayName?, avatarMediaId? }`. `email`, `roles`, `status`, `dateOfBirth` are **not** writable here (email change goes through Better Auth's change-email flow with re-verification).
- **200:** `Me`.
- **Errors:** `VALIDATION_FAILED` (unknown field e.g. `roles`), `CONFLICT` (username taken), `UNAUTHENTICATED`.
- **Side effects:** none (no audit for self-edits). PROPOSED: username change at most once per 30 days → `INVALID_STATE { details.nextChangeAt }`.
- **Tests:** can change displayName; attempt to set `roles: ["admin"]` → 400; username clash → 409.

#### AUTH-08 `DELETE /api/me` — CONFIRMED (decision 17)

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/api.test.ts`
- Body `{ password }` (re-auth). **202** `{ status: "pending_deletion", purgeAt }`. Sessions revoked; user hidden from all public reads immediately. Signing in within 30 days restores the account. After 30 days a daily job (OPS-03) erases email, DOB, profile, avatar and private evidence; replies show "Deleted user"; XP ledger and audit rows keep an anonymous ID; Originals position is retired, never reassigned. Data export is by email request (no route).
