## 7. Missions, completions, XP, badges

> **Rules decided (decisions 10–11).** Talent picks `auto` or proof `review` per mission; proof = link or text; one completion per fan; none after deadline; XP granted at most once via the ledger's unique key. Fan-created missions are post-launch. Build order per PRD §11 still applies: ledger + idempotency tests first.

Mission state machine (PROPOSED): `pending → approved | rejected`; `approved → expired` (time-based, `deadline < now()`, computed not job-driven) `| closed` (owner closes). Only `approved` and not expired accepts completions. Only an approved completion grants XP.

Status: :badge[implemented]{color="success"}

- **Caller:** Public/members see only `approved` (incl. computed `expired` if `status=expired` requested); owner/admin may filter `pending|rejected`. Fans see their own `pending` mission posts.
- **Query:** `communityId?`, `status? = active|expired|pending|rejected` (default `active` = approved & not expired), `limit`, `cursor`.

- **Errors:** `FORBIDDEN` (fan asking `status=pending` for a community they don't own — returns only own items instead? PROPOSED: silently scope to own items, not error).
- **Tests:** pending missions invisible to other fans (PRD §6.6); expired excluded from `active`.

#### MIS-03 `POST /api/missions` — CONFIRMED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/missions.test.ts`
- **Caller:** community owner (talent) or admin → created `approved`. Fans → `FORBIDDEN` (fan missions post-launch; the `pending` status and MIS-04/05 stay in the model for that).
- **Body:** `{ communityId, title (≤120), description (≤2000), xpReward (int within admin range from ADM-15, else `VALIDATION_FAILED`), deadline?: ISO future, completionPolicy: { review: 'auto'|'owner', proof: 'none'|'link'|'text' } }`. `review:'auto'` requires `proof:'none'|'link'|'text'` but grants XP immediately; `review:'owner'` requires `proof` ≠ `none`.
- **201:** `Mission`. Optional `Idempotency-Key`.
- **Errors:** `VALIDATION_FAILED` (xpReward outside admin-configured bounds), `FORBIDDEN` (not member), `NOT_FOUND`.
- **Tests:** fan-created → `pending` and hidden; owner-created → `approved`.

#### MIS-06 `POST /api/missions/:id/completions` — CONFIRMED

Status: :badge[implemented]{color="success"}
- **Proof:** `tests/e2e/missions.test.ts`
- **Caller:** active member of the mission's community. **Body:** `{ proof?: <shape per completionPolicy> }`.
- **201 (new) / 200 (existing, non-repeatable):** `Completion`. If `review = auto` → `approved` immediately and XP granted in the **same transaction**; if `owner` → `submitted`.
- **Errors:** `INVALID_STATE` (mission pending/rejected/expired/closed → *no XP*, acceptance #8); `FORBIDDEN reason:"not_member"`; `VALIDATION_FAILED` (proof missing/invalid); `NOT_FOUND`.
- **Concurrency:** unique `(missionId, userId)` for non-repeatable missions; XP ledger unique `(userId, 'mission_completion', completionId)`.
- **Tests:** 10 parallel submissions → 1 completion, 1 ledger row; expired mission → 409 no ledger row; balance equals ledger sum (acceptance #9).
