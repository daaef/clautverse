## 6. Feed, drops, reactions, replies

Content-access rule (server-side, every read): a drop's full `body`/`media` is returned only if the viewer is entitled under the drop's `audience` — `public` (anyone, even signed out), `members` (default; active members), `originals_only` (members holding an Originals position). Otherwise `locked: true`, `body: null`, `media: null`, and `preview = { type, author, publishedAt, teaser }` where `teaser` is the optional talent-written line (≤100 chars). No text excerpt, no media URL, no blurred thumbnail — signed media URLs never reach locked viewers (decisions 7–8).

#### FEED-01 `GET /api/feed?communityId=&from=&to=&limit=&cursor=` — CONFIRMED

Status: :badge[planned]{color="neutral"}
- **Purpose:** Home feed — published drops from communities I've joined.
- **Caller:** Signed-in user. Only `active` memberships contribute.
- **Query:** `communityId?` (must be one of my active memberships, else `FORBIDDEN reason:"not_member"`), `from?`/`to?` (ISO, `from < to`, max 90-day window), `limit`, `cursor`.
- **200:** `{ items: Drop[], nextCursor }` sorted `publishedAt desc, id desc`. Only `status = published` and `publishedAt <= now()` (scheduled items appear when due without a job, because the filter is time-based). `originals_only` drops in my communities appear `locked` (with teaser) if I'm not an Original.
- **Errors:** `VALIDATION_FAILED` (bad dates, window too large, cursor mismatch), `FORBIDDEN`, `UNAUTHENTICATED`.
- **Tests:** draft/scheduled-in-future never returned; no duplicates across 3 pages while new drops are inserted between page fetches (acceptance #7); left community's drops disappear; non-member communityId → 403.

#### FEED-02 `GET /api/communities/:id/drops` — CONFIRMED (public timeline incl. locked cards for non-entitled viewers; decisions 7–8)

Status: :badge[planned]{color="neutral"}
- **Why separate:** FEED-01 is "my joined communities"; this is the community page timeline that **non-members** also hit to see locked previews (PRD "fans must join to see full posts" implies they see *something*). Merging them would make FEED-01's auth/visibility rules conditional.
- **Caller:** Public. **Query:** `type?`, `limit`, `cursor`. **200:** `{ items: Drop[], nextCursor }`, `publishedAt desc, id desc`; locked for non-entitled viewers.
- **Tests:** signed-out viewer gets `locked: true` + `body: null` + `media: null` for members-only drops (acceptance #5); member gets body.

#### DROP-01 `POST /api/drops` — CONFIRMED (talents only; fan drops post-launch — decision 9)

Status: :badge[planned]{color="neutral"}
- **Purpose:** Talent publishes a text/voice/image drop.
- **Caller:** Community owner (talent) or admin. Fans → `FORBIDDEN`.
- **Headers:** optional `Idempotency-Key`.
- **Body:** `{ communityId, type: 'text'|'voice'|'image', body? (≤5000; required for text), mediaIds?: string[] (required for voice/image; uploaded via MED-01), audience: 'public'|'members'|'originals_only' (default `members`), teaser?: string(≤100), publishAt?: ISO (future → scheduled; omitted → draft), publishNow?: boolean }`.
- **201:** `Drop` (`status: draft|scheduled|published`).
- **Errors:** `VALIDATION_FAILED` (type/body/media mismatch, publishAt in past, unknown audience); `FORBIDDEN` (not owner); `NOT_FOUND` (community).
- **Side effects:** on publish, in-app notification to members with `alertsEnabled` (decision 13). For `originals_only`, non-Original members get the notification with the locked card.
- **Tests:** fan → 403 (acceptance #10); voice without media → 400; scheduled drop absent from feed until `publishAt`; idempotency key replay returns same id.

#### DROP-02 `GET /api/drops/:id` — CONFIRMED

Status: :badge[planned]{color="neutral"}
- **Caller:** Public; entitlement applied. Drafts/scheduled visible only to author/owner/admin, otherwise `NOT_FOUND`.
- **200:** `Drop`. **Tests:** draft → 404 for fan; locked shape for non-member.

#### DROP-03 `PATCH /api/drops/:id` — CONFIRMED (edit rules PROPOSED)

Status: :badge[planned]{color="neutral"}
- **Caller:** author or admin. **Body:** `{ body?, teaser?, audience?, publishAt? }`. PROPOSED: drafts/scheduled fully editable; published drops allow `body`/`teaser` edits only (sets `editedAt`); `audience` cannot change after publish → `INVALID_STATE`.
- **Errors:** `NOT_FOUND`, `FORBIDDEN`, `INVALID_STATE` (removed/archived), `VALIDATION_FAILED`.
- **Tests:** non-author 403; edit on removed drop 409.

#### DROP-04 `POST /api/drops/:id/publish` — PROPOSED (explicit transition instead of `PATCH {status}`)

Status: :badge[planned]{color="neutral"}
- **Body:** `{ publishAt?: ISO }` (omit = now). Allowed: `draft → scheduled|published`, `scheduled → published|scheduled` (reschedule). **200:** `Drop`. Repeat on already published → 200 unchanged. Other transitions → `INVALID_STATE`.

#### DROP-05 `DELETE /api/drops/:id` — PROPOSED · author or admin; soft delete; replies hidden with it; admin → audit.

Status: :badge[planned]{color="neutral"}
- **Caller:** author or admin. Soft delete → `status: archived` (author) / `removed` (admin moderation, via ADM-12). **204.** Repeat → 204.
- **Side effects:** admin removal → `AdminAudit`.

#### DROP-06 `PUT /api/drops/:id/reactions/me` — CONFIRMED (**replaces** PRD `POST /reactions`; one like per fan per drop)

Status: :badge[planned]{color="neutral"}
- **Why PUT:** one reaction per user per drop (PROPOSED) makes "set my reaction" naturally idempotent; no duplicate-reaction race.
- **Caller:** signed-in, onboarded user entitled to the drop. **Body:** none (`like` is the only reaction at launch).
- **200:** `{ dropId, type, reactionCounts }`. **Errors:** `FORBIDDEN reason:"locked"`, `NOT_FOUND`, `VALIDATION_FAILED`.
- **Tests:** repeated PUT keeps count at 1; changing type moves the count; locked drop → 403.

#### DROP-07 `DELETE /api/drops/:id/reactions/me` — PROPOSED · **204**, idempotent.

Status: :badge[planned]{color="neutral"}

#### DROP-08 `GET /api/drops/:id/replies` — CONFIRMED · entitled viewers only.

Status: :badge[planned]{color="neutral"}
- **Caller:** entitled viewer. **200:** `{ items: Reply{ id, dropId, author: PublicUser, body, createdAt, editedAt|null, status }[], nextCursor }` sorted `createdAt asc, id asc` (conversation order). Removed replies → `body: null, status: "removed"` placeholder.
- **Errors:** `FORBIDDEN reason:"locked"`, `NOT_FOUND`.

#### DROP-09 `POST /api/drops/:id/replies` — CONFIRMED

Status: :badge[planned]{color="neutral"}
- **Caller:** active member entitled to the drop (a public drop can be read by anyone, but only members reply). **Body:** `{ body (1..1000), parentReplyId? }` (one level of nesting). Optional `Idempotency-Key`. **201:** `Reply`.
- **Errors:** `FORBIDDEN`, `NOT_FOUND`, `VALIDATION_FAILED`, `RATE_LIMITED`.
- **Side effects:** if `parentReplyId`, in-app notification to that reply's author (not self).
- **Tests:** non-member 403; empty body 400; rate limit.

#### DROP-10 `DELETE /api/replies/:id` — CONFIRMED · author, community owner (talent), or admin. Soft delete. **204**. Admin → audit.

Status: :badge[planned]{color="neutral"}

#### RPT-01 `POST /api/reports` — PROPOSED (missing in PRD; admin can list reports but nothing creates them)

Status: :badge[planned]{color="neutral"}
- **Purpose:** Fan reports a drop, reply, user, community or mission.
- **Caller:** signed-in user. **Body:** `{ targetType: 'drop'|'reply'|'user'|'community'|'mission', targetId, reason: 'spam'|'harassment'|'hate'|'sexual'|'impersonation'|'other'
- **201:** `{ id, status: "open", createdAt }` — reporter is never revealed to the reported user and does not see the outcome. One open report per reporter per target → repeat returns the existing report (200).
- **Idempotency:** one open report per `(reporter, target)`; repeat → `200` existing report.
- **Errors:** `NOT_FOUND` (target), `VALIDATION_FAILED`, `RATE_LIMITED`.
- **Tests:** duplicate report returns same id; reporter identity not exposed to reported user anywhere.
