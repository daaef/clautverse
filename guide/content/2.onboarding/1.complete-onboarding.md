## Outcome

A signed-in, verified fan sends their picks once more and Clautverse marks onboarding as `completed`. After this, the app stops showing onboarding screens. Completing onboarding does **not** join any community: joining can hand out an Originals number, so it must be the fan's own choice.

## Concept map

The **shared concept** is an API route that validates input, checks who is calling, and writes to the database in one transaction.

- **Nuxt/Nitro (canonical):** the file name decides the route. `complete.post.ts` inside `server/api/onboarding/` answers `POST /api/onboarding/complete`.
- **Next.js equivalent:** `app/api/onboarding/complete/route.ts` exporting `async function POST(request)`. Zod and Drizzle are used the same way.

## Prerequisites

- The [local setup](/getting-started/local-setup) is running, including `pnpm db:seed` (it adds Reality TV, BBNaija and a few talents).
- You can sign up and verify an email (Better Auth, AUTH-01 and AUTH-04b).

## Implementation steps

::guide-section{id="onboarding-complete-handler" title="Onboarding complete handler" type="code" file-path="server/api/onboarding/complete.post.ts" expected-result="200 with { status: 'completed', nextStep: null, selections }" verification="Run pnpm test:e2e and check 'saves progress, resumes, then completes' passes" references="Nitro route handlers https://nitro.build/guide/routing|Zod objects https://zod.dev/api#objects|Drizzle transactions https://orm.drizzle.team/docs/transactions"}
```ts [server/api/onboarding/complete.post.ts]
import { eq } from 'drizzle-orm'
import { z } from 'zod'

// ONB-03: Reality TV (an active category) + at least one show required; the rest optional (decision 2b).
const body = z.object({
  categoryId: z.uuid(),
  countryId: z.uuid().nullable().optional(),
  showIds: z.array(z.uuid()).min(1, 'pick at least one show').max(20),
  seasonIds: z.array(z.uuid()).max(50).optional(),
  talentIds: z.array(z.uuid()).max(50).optional(),
}).strict()

export default defineEventHandler(async (event) => {
  const me = await requireUser(event)
  await rateLimit(event, 'onboarding-complete', me.id, 20, 60)
  const input = await readJsonBody(event, body)
  const sel = await validateSelections(input)
  const db = useDb()
  const now = new Date()
  const [row] = await db.transaction(async (tx) => {
    await tx.update(schema.user).set({ onboardingStatus: 'completed', updatedAt: now }).where(eq(schema.user.id, me.id))
    return tx.insert(schema.onboarding).values({ userId: me.id, ...sel, completedAt: now, updatedAt: now })
      .onConflictDoUpdate({ target: schema.onboarding.userId, set: { ...sel, completedAt: now, updatedAt: now } }).returning()
  })
  return onboardingView('completed', row)
})
```
::

## Code explanation

::guide-section{id="onboarding-complete-explanation" title="What each block does" type="explanation"}
- **The Zod `body` schema** describes the only accepted shape. `.strict()` rejects unknown fields. `showIds` must have at least one ID, which is the "at least one show" rule.
- **`requireUser(event)`** stops anyone who is signed out (`UNAUTHENTICATED`), suspended (`ACCOUNT_SUSPENDED`) or unverified (`EMAIL_NOT_VERIFIED`).
- **`rateLimit(...)`** allows 20 calls a minute per user, stored in PostgreSQL.
- **`validateSelections`** checks the IDs really exist: the category must be active (so "Music – coming soon" is refused), shows must be active and in that category, and seasons must belong to the chosen shows.
- **The transaction** updates the user and saves the picks together. If either write fails, neither is kept.
- Calling it again is safe: it just saves the latest picks.
::

## Troubleshooting

- `403 EMAIL_NOT_VERIFIED`: open the verification link printed in the API terminal, then retry.
- `400` with `categoryId: "inactive"`: you sent a "coming soon" category. Use Reality TV.
